# Codebase review — 2026-10-01

Scope: `daemon_v2.py`, `ReceiverActivity_v2.java`, `start.sh`, build files,
repo layout. Findings are from reading the code unless marked *tested*.
Status of each item is tracked in the last section.

## A. Latency and correctness

**A1 — Receiver holds the newest frame back.**
`ReceiverActivity_v2.java` `pump()` feeds an access unit only once the *next*
AUD arrives, because Annex B marks where an AU starts, never where it ends.
The latest frame therefore sits in the accumulator until the screen changes
again. Cost: one full frame interval (17 ms at 60 fps, 45–77 ms at the
13–22 fps where Phase 6 measured 85–95 ms "decode"). Probably also the
"cursor ghost" accepted in `phase6_spec.md`: the frame that erases the cursor
is the last of its burst (hypothesis, not confirmed on hardware).
Fix: length-prefixed framing, which needs packet boundaries from the muxer.

**A2 — Forced keyframes are frame-count, not wall-clock.** *(tested)*
Commit `625c03d` removed `-use_wallclock_as_timestamps`, so the rawvideo
demuxer stamps PTS by frame count and `force_key_frames expr:gte(t,…)`
fires every 30 *frames*. 20 frames fed over 4 s produced 1 IDR, not 8. At
idle 5 fps the "0.5 s" recovery bound is ~6 s. The comment in
`build_ffmpeg_cmd` and the sender contract in `phase6_spec.md` are false.

**A3 — Tail drain blocks ≥5 ms on every socket read.**
`drain(decoder, info, TAIL_DRAIN_TIMEOUT_US)` runs once per read chunk even
when no AU was fed, and loops until a 5 ms wait times out. A keyframe
arriving in a dozen chunks costs ~60 ms of waiting with the socket unread.

## B. Robustness

**B1 — Dead clients are only noticed when a send fails.** The acceptor
parks in `_dead.wait()`; on a static screen nothing is sent, so a relaunched
app waits in the listen backlog behind the dead socket.

**B2 — A stalled client freezes the daemon.** `sendall` has no timeout; the
back-pressure chain (socket → relay thread → ffmpeg stdout → ffmpeg stdin)
ends with the evdi thread blocked while holding `restart_lock`.

**B3 — Stream exposed to the LAN.** Binds `0.0.0.0:7070`, unauthenticated;
`adb reverse` only needs loopback.

**B4 — `surfaceDestroyed` does not stop the rx thread.** `interrupt()` does
not unblock a `java.net.Socket` read, so background/resume can leave two
threads and two sockets, and a thread still using a destroyed Surface.

**B5 — An ffmpeg crash ends the daemon**, taking the virtual display with it.

## C. Repo hygiene

* **C1** No remote. The required pyevdi patch (`4ad462a`) exists only in the
  nested `evdi-src` clone (gitlink without `.gitmodules`).
* **C2** `tools/gradle-8.7` (143 MB, 268 files) is tracked despite
  `.gitignore`; the Gradle wrapper already covers it.
* **C3** No unit tests in the repo (the Phase 6 ones lived in `/tmp`).
* **C4** `start.sh --legacy` launches `.ReceiverActivity`, which is not in
  the manifest. `daemon_v1.py` and `android/_archive/` are dead.
* **C5** `TABDISPLAY_PORT` is not passed to the daemon; module docstring
  describes the numpy path; a `start.sh` comment says 10 s for the 3 s
  watchdog; no README.

## D. Structure

* **D1** `run()` is ~220 lines of closures over `state`/`stats` dicts.
* **D2** Mode dicts compared by identity and mutated globally.
* **D3** The numpy `nv12` path uses BT.601 coefficients but is tagged BT.709
  under `--csc gpu`.

## Status

Work is on branch `review-fixes`. Nothing here has run against the tablet
or a live evdi display yet — see "Not yet verified" below.

| Item | Status | What changed |
|---|---|---|
| A1 | fixed | Wire format is now `[u32 length][AU]`. ffmpeg reports each packet's size on a side pipe (`tee` to `framecrc` + `h264`); `read_access_units` pairs the two. Receiver reads whole frames with `FrameReader`; no AUD scanning. |
| A2 | fixed | Frames are stamped with wall-clock time in the filter graph (`settb`/`setpts=RTCTIME-RTCSTART`, `-fps_mode passthrough`, µs encoder time base). Tested on the real encoder: 10 frames over 2.5 s give ≥4 IDRs, one packet per frame, no warnings in a burst. |
| A3 | fixed | Decoder runs in async mode; output is rendered from the codec callback. No polling drains remain. |
| B1 | fixed | Newest connection replaces the current client. |
| B2 | fixed | 2 s send timeout; a stalled client is dropped. |
| B3 | fixed | Binds `127.0.0.1` by default (`--bind` to widen). Bind errors now fail startup instead of killing the acceptor thread silently. |
| B4 | fixed | `surfaceDestroyed` closes the socket and joins the rx thread. |
| B5 | fixed | A failed write respawns ffmpeg and re-feeds the frame; gives up after 3 deaths in 10 s. |
| C1 | partly | Patch saved in `patches/`, rebuild steps in `README.md`. Still no remote — needs a decision on where to host. |

### Not yet verified

No tablet was attached, and starting the daemon would add a monitor to the
live desktop, so these still need a hands-on pass:

1. Install the new APK and run `./start.sh` — picture appears, steady
   `decoded N frames` in logcat.
2. Cursor ghost: flick the pointer off the tablet screen. If A1 was the
   cause, the ghost no longer sticks.
3. Unplug/replug and force-stop/relaunch the app on a static screen —
   picture returns without touching the desktop.
4. Background and resume the app — one connection in the daemon log.
5. Fullscreen video round trip (auto mode) still switches both ways.

### Spec changes

`phase6_spec.md` R2, R3 and R4 are superseded, and R10 is relaxed; the
spec carries a note. Daemon and app must be updated together: there is no
protocol version negotiation.
